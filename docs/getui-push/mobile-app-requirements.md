# 个推推送手机 App — 需求文档

## 1. 项目背景

### 1.1 项目概述

本项目是一个基于 **uni-app** 框架开发的手机应用（以下简称"个推App"），目标平台为 **Android** 和 **鸿蒙 Next（HarmonyOS Next）**。该应用的核心功能是接收 Rocket.Chat 服务端通过**个推（GeTui）**推送的消息通知，并能跳转到 Rocket.Chat 官方 App 查看消息详情。

### 1.2 应用定位

本应用定位为 Rocket.Chat 的**推送通知伴侣应用（Push Companion App）**，不是一个完整的聊天客户端。其核心价值在于为中国大陆用户提供可靠的消息推送通道。

### 1.3 关联应用

| 应用 | 说明 | 推送方式 |
|------|------|----------|
| Rocket.Chat 官方 App | React Native 应用，完整聊天客户端 | FCM（国内不可用）或无推送 |
| 个推App（本项目） | uni-app 轻量伴侣应用 | 个推（国内可用） |

### 1.4 名词定义

| 术语 | 说明 |
|------|------|
| uni-app | DCloud 开发的跨平台应用框架，支持 Android、iOS、鸿蒙等 |
| 个推（GeTui） | 国内推送服务，支持 Android 和鸿蒙 Next 推送通道 |
| CID | 个推客户端标识，SDK 为每个设备生成的唯一推送 ID |
| 官方App | Rocket.Chat 官方 React Native 移动应用 |
| Deep Link | 应用间跳转链接，用于从个推App跳转到官方App |

## 2. 目标用户

- 使用 Rocket.Chat 作为团队通信工具的中国大陆用户
- 需要在 Android 或鸿蒙 Next 设备上接收 Rocket.Chat 消息推送的用户
- 已安装或即将安装 Rocket.Chat 官方 App 的用户

### 3.2 MR-001: 用户登录

#### 3.2.1 描述

用户需要登录 Rocket.Chat 服务器以关联推送 Token。服务端已配置 OAuth 认证（禁止直接注册账号），本应用采用 **OAuth 2.0 PKCE（Proof Key for Code Exchange）** 流程进行登录。PKCE 专为无法安全存储客户端密钥的公共客户端（如手机 App）设计，即使 APK 被反编译也不会泄露任何密钥。

#### 3.2.2 功能要求

- **FR-001-1**: 提供服务器地址输入界面，用户输入 Rocket.Chat 服务器 URL
- **FR-001-2**: 验证服务器地址有效性（调用 `/api/v1/info` 接口）
- **FR-001-3**: 应用在本地生成 `code_verifier`（随机高熵字符串）及对应的 `code_challenge`（`BASE64URL(SHA256(code_verifier))`）
- **FR-001-4**: 打开 WebView 加载服务器 OAuth 授权页面（`/oauth/authorize?response_type=code&client_id=...&code_challenge=...&code_challenge_method=S256&redirect_uri=...`），服务器端会通过已配置的 OAuth 提供商完成身份验证
- **FR-001-5**: WebView 拦截重定向 URL，从中提取授权码（`code`）
- **FR-001-6**: 应用使用授权码 + `code_verifier` 调用 `/oauth/token`，**无需** `client_secret`，换取访问令牌及用户信息（通过 `userId` 与服务端已有 OAuth 用户匹配）
- **FR-001-7**: 安全存储认证信息（使用设备安全存储）
- **FR-001-8**: 支持自动登录（使用已保存的认证信息）
- **FR-001-9**: 登录成功后自动注册个推 Token

#### 3.2.3 OAuth PKCE 登录流程

```
用户输入服务器地址
  → 验证服务器 (/api/v1/info)
  → 生成 code_verifier（随机 64 字节，Base64URL 编码）
  → 计算 code_challenge = BASE64URL(SHA256(code_verifier))
  → 打开 WebView:
      {serverUrl}/oauth/authorize
        ?response_type=code
        &client_id={publicClientId}
        &redirect_uri=rcpush://oauth
        &code_challenge={code_challenge}
        &code_challenge_method=S256
  → 服务器通过已有 OAuth 提供商完成身份验证
  → 服务器重定向至 rcpush://oauth?code={authCode}
  → WebView 拦截重定向，关闭 WebView，提取 authCode
  → POST {serverUrl}/oauth/token
      { grant_type: 'authorization_code',
        code: authCode,
        redirect_uri: 'rcpush://oauth',
        client_id: publicClientId,
        code_verifier: code_verifier }
  → 获取 access_token（即 RC authToken）及用户 ID
  → 保存认证信息
  → 登录成功
```

#### 3.2.4 验收标准

- 用户可输入有效的 Rocket.Chat 服务器地址
- 无效地址给出明确错误提示
- OAuth PKCE 流程完成后能正确获取认证信息
- 认证信息安全存储，不明文保存
- 应用重启后能自动登录
- 登录成功后个推 Token 自动注册

### 3.3 MR-002: 个推 SDK 集成

#### 3.3.1 描述

集成个推推送 SDK，支持 Android 和鸿蒙 Next 平台的推送通道。

#### 3.3.2 功能要求

- **FR-002-1**: 集成个推 uni-app 插件（[uni-push](https://uniapp.dcloud.net.cn/unipush-v2.html) 或个推原生插件）
- **FR-002-2**: 应用启动时初始化个推 SDK
- **FR-002-3**: 获取设备 CID（Client ID）
- **FR-002-4**: 监听 CID 变化事件（CID 可能在 SDK 重新连接时改变）
- **FR-002-5**: 支持 Android 厂商通道（小米、华为、OPPO、vivo 等）以提高推送到达率
- **FR-002-6**: 支持鸿蒙 Next 推送通道

#### 3.3.3 个推 SDK 配置

```
Android 端:
- 个推 App ID / App Key / App Secret
- 厂商通道配置（可选，提高到达率）:
  - 小米推送: AppID, AppKey
  - 华为推送: AppID, AppSecret
  - OPPO 推送: AppKey, AppSecret
  - vivo 推送: AppID, AppKey

鸿蒙 Next 端:
- 个推 App ID / App Key / App Secret
- HMS Push Kit 配置
```

#### 3.3.4 验收标准

- 应用启动后能成功初始化个推 SDK
- 能获取到有效的 CID
- CID 变化时能触发回调
- Android 和鸿蒙 Next 平台均能正常工作

### 3.4 MR-003: Token 注册

#### 3.4.1 描述

将个推 CID 注册到 Rocket.Chat 服务端，建立用户与推送通道的关联。

#### 3.4.2 功能要求

- **FR-003-1**: 用户登录成功后自动注册 CID
- **FR-003-2**: CID 变化时重新注册
- **FR-003-3**: 调用服务端 `POST /api/v1/getui.token` 注册
- **FR-003-4**: 注册失败时进行重试（最多 3 次，指数退避）
- **FR-003-5**: Token 注册状态在本地持久化，避免重复注册

#### 3.4.3 验收标准

- 登录后 CID 被成功注册到服务端
- CID 变化后新 CID 被重新注册
- 注册失败时有重试机制
- 不会重复注册相同的 CID

### 3.6 MR-005: 点击推送跳转

#### 3.6.1 描述

用户点击推送通知后，应尝试跳转到 Rocket.Chat 官方 App 的对应消息位置。**禁止**使用 WebView 打开具体消息页面；如官方 App 未安装，则在应用内以原生界面显示通知摘要信息。

#### 3.6.2 功能要求

- **FR-005-1**: 点击通知后尝试通过 Deep Link 打开官方 App
- **FR-005-2**: Deep Link 格式: `rocketchat://room/{rid}?messageId={msgId}&host={serverUrl}`
- **FR-005-3**: 如果官方 App 未安装，或 Deep Link 跳转失败，则在应用内使用**原生通知详情页**展示通知摘要（标题、正文、发送者、频道），不使用 WebView
- **FR-005-4**: 原生通知详情页提供"打开 Rocket.Chat 官方 App"或"前往应用市场下载"的按钮

#### 3.6.3 跳转流程

```
用户点击推送通知
  → 解析通知负载 (rid, msgId, host, roomName, senderName)
  → 检查官方 App 是否安装
  ├─ 已安装 → 构建 Deep Link → 尝试跳转
  │           ├─ 跳转成功 → 完成
  │           └─ 跳转失败 → 跳转到原生通知详情页
  └─ 未安装 → 跳转到原生通知详情页（不使用 WebView）
```

#### 3.6.4 验收标准

- 点击通知后能尝试跳转到官方 App
- 官方 App 未安装或跳转失败时，回退到原生通知详情页（无 WebView）
- 整个跳转过程中不打开任何 WebView 页面
- 跳转过程流畅，无明显延迟

- **FR-006-6**: 支持在设置页面修改服务器地址

#### 3.7.3 验收标准

- 首次启动显示服务器配置引导

- 无效地址或不支持个推的服务器给出提示
- 服务器配置持久保存

### 3.8 MR-007: 登出与 Token 清理

#### 3.8.1 描述

用户登出时清理个推 Token，防止收到非自己的推送。

#### 3.8.2 功能要求

- **FR-007-1**: 提供登出按钮
- **FR-007-2**: 登出时调用 `DELETE /api/v1/getui.token` 删除服务端 Token
- **FR-007-3**: 清除本地存储的认证信息
- **FR-007-4**: 登出失败（网络问题）时仍清除本地信息，并在下次联网时重试清理服务端 Token
- **FR-007-5**: 登出后跳转到服务器配置/登录页面

#### 3.8.3 验收标准

- 登出后不再收到推送通知
- 本地认证信息被清除
- 登出后显示登录页面

#### 3.9.1 描述

支持同时连接多个 Rocket.Chat 服务器的推送。

#### 3.9.2 功能要求

- **FR-008-1**: 支持添加多个服务器
- **FR-008-2**: 每个服务器独立登录和管理 Token
- **FR-008-3**: 推送通知中显示服务器来源
- **FR-008-4**: 支持移除已添加的服务器

#### 3.9.3 验收标准

- 可同时接收来自多个服务器的推送
- 每个服务器的 Token 独立管理
- 推送通知能区分来源服务器

## 6. 约束与假设

### 6.1 约束

1. **框架限制**: 使用 uni-app 框架，需依赖 DCloud 插件生态
2. **平台限制**: 仅支持 Android 和鸿蒙 Next，不支持 iOS
3. **推送依赖**: 依赖个推 SDK 和个推推送通道
4. **官方App兼容**: 跳转功能受限于官方App对 Deep Link 的支持程度
5. **鸿蒙 Next 限制**: 鸿蒙 Next 的 uni-app 支持可能尚不完善，需评估
6. **WebView 限制**: 应用内 WebView **仅**允许用于 OAuth 登录流程，其他页面（含消息详情）必须使用原生界面
7. **鉴权限制**: 不得在 App 中嵌入 OAuth client_secret；使用 PKCE 流程确保即使 APK 被反编译也不会泄露密钥

### 6.2 假设

1. 用户设备已能正常访问配置的 Rocket.Chat 服务器
2. Rocket.Chat 服务端已部署个推推送集成
3. 个推 SDK 的 uni-app 插件支持鸿蒙 Next 平台
4. 官方 App 支持 `rocketchat://` URL Scheme
5. 用户设备允许应用的后台运行权限
